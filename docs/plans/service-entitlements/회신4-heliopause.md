# heliopause 팀에 — SET 계약에 키 두 개를 더합니다 (파서 만들기 전에)

회신 2026-08-06 · 앞선 왕복: `회신3-heliopause.md` → `heliopause/docs/keystone-답신2.md`
근거: KeyStone `feat/service-entitlements` 실측

---

## 요약

**`{ roles, entitlements }` 로 확정이라고 알려 드렸는데, 같은 event 객체 밖에 클레임 두 개를 더
넣습니다.** 아직 파서를 안 만드셨다고 하셨으니 지금 알리는 게 맞다고 봤습니다.

```
iss / aud / sub / iat / jti / events        ← 기존, 그대로
exp                                          ← 추가: 재생 상한
txn                                          ← 추가: 스냅샷 순서 표식 (ms 문자열)
```

`events[...]` 안의 `{ roles, entitlements }` 는 **바뀌지 않습니다.** 그 안을 읽는 코드는 그대로
두시면 됩니다.

---

## 왜 필요한지 — 회수가 조용히 되돌아갈 수 있습니다

독립 리뷰에서 나온 지적이고, 저희가 맞다고 판단했습니다.

이 SET 은 델타가 아니라 **변경 후 전체 상태 스냅샷**입니다. 그런데 발행이 fire-and-forget 이고
재시도가 없습니다. 그래서 이런 순서가 가능합니다.

```
T+0.0s  관리자가 plan.publish 부여   → SET A = { entitlements: ["plan.publish"] }
T+0.3s  실수를 깨닫고 회수           → SET B = { entitlements: [] }

두 발행은 서로 다른 Worker 실행에서 각각 fetch 합니다.
B 가 A 보다 먼저 도착하면 → RP 의 최종 상태는 ["plan.publish"]
```

**회수가 뒤집히고, RP 는 그것을 알 방법이 없습니다.** `iat` 는 초 단위라 같은 초에 난 두 변경을
구분하지 못합니다.

그래서 `txn` 을 넣습니다 — 발행 시각의 밀리초 값입니다.

**그쪽에서 하실 일: 마지막으로 적용한 `txn` 을 기억하고, 그보다 작거나 같은 SET 은 버리세요.**
문자열로 보내지만 숫자로 비교하시면 됩니다.

`exp` 는 별개로 지연 도착한 오래된 스냅샷의 재생 상한입니다(현재 300초). 만료된 SET 은
거부하시면 됩니다.

## 그 밖에 바뀐 것 — 그쪽이 받는 것에 영향 있는 것만

**발행 지점이 넷이 됐습니다.** 배정 부여 · 배정 회수 · **권한만 변경** · **만료 변경**.
마지막 두 개가 새로 붙었습니다. 특히 만료를 미래로 미는 것은 만료됐던 배정과 그 권한을
되살리는 일이라 통지가 필요했습니다.

**권한 키는 소문자로 정규화됩니다.** `Site.Read` 로 등록해도 `site.read` 로 저장·발행됩니다.
스케치해 주신 다섯 개는 이미 전부 소문자라 영향 없습니다. (이유: 유니크 인덱스에 collation 이
없어 MySQL 은 대소문자를 구분하지 않는데 PostgreSQL/SQLite 는 구분해서, 같은 키의 다른 표기가
방언에 따라 **둘 다 클레임에 실릴 수** 있었습니다.)

**관리자 강제 로그아웃이 이제 그쪽에 도달합니다.** 지난번(회신2 §7)에 "필요하다" 고 하셔서
넣었습니다. back-channel logout 을 주체 단위로 보냅니다 — `backchannel_logout_session_required`
체크박스를 **꺼 두시면** `sub` 만 실린 토큰을 받고, 그 사용자의 세션을 전부 끊으시면 됩니다.

배선만으로는 부족했다는 것도 적어 둡니다. 기존 타깃 탐색이 `oidcGrants`(수 분 TTL, GC 삭제)와
`oidcRefreshTokens`(offline_access 필요)에 묶여 있어서, **그쪽처럼 offline_access 를 안 쓰는 RP 는
로그인 몇 분 뒤부터 탐색되지 않았습니다.** 그대로 배선했으면 여전히 도달하지 못했을 겁니다.
지금은 배정/allowAllUsers 기준의 주체 단위 탐색을 씁니다.

## 진행 상황

**P1~P6 전부 완료**했습니다. OIDC 경로는 권한 정의 → 사용자 배정 → 클레임 발행 → SET 통지까지
닫혔습니다. SAML 은 attribute 명이 미정이라 발행·정의 UI 를 함께 보류했습니다 — 정의만 먼저 넣으면
관리자가 권한을 만들고 배정했는데 SP 에는 아무것도 안 가는 조용한 무동작이 됩니다.

독립 리뷰 두 건(코드·보안)을 받았고, 지적을 전부 반영했습니다. 가장 무거웠던 것은 **권한 정의를
삭제하면 모든 보유자의 권한이 사라지는데 아무에게도 알리지 않고 아무것도 기록하지 않던 것**입니다.
게다가 감사에 id 만 남겨서, 정의가 지워지면 "누가 그 권한을 갖고 있었나" 에 영영 답할 수 없었습니다.
지금은 보유자별로 key 와 함께 기록하고, refresh 를 폐기하고, SET 을 보냅니다.
